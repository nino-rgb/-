# VSPO Live Go版 同期処理仕様

> 本書は今回確定した同期運用・DB反映の仕様をまとめたもの。外部APIの全パラメータ等は別途既存のAPI仕様・調査資料を参照する。

## 1. 実行スケジュール

| 項目 | YouTube | Twitch |
|---|---|---|
| 起動時 | 1回実行 | 1回実行 |
| 定期実行 | 毎時00分 | 毎時30分 |
| 時刻基準 | JST (`Asia/Tokyo`) | JST (`Asia/Tokyo`) |
| 実行頻度 | 1時間に1回 | 1時間に1回 |
| 同一プラットフォームの重複実行 | 前回実行中ならスキップ | 前回実行中ならスキップ |
| 同期失敗時 | 次回定期同期で再試行 | 次回定期同期で再試行 |

- 定期実行時刻はサーバーの起動時刻に依存しない。
- YouTubeとTwitchは独立して動作する。一方の失敗で他方を停止しない。
- 同一プラットフォームの起動時同期と定期同期が重なった場合も重複起動させない。

## 2. 同期の基本手順

1. Clientが外部APIを呼び出し、必要なデータの取得完了・成功を確認する。
2. API取得失敗時は該当同期のDB変更を行わない。
3. RepositoryがDBトランザクションを開始し、対象の最新DB状態をロックして読み取る。
4. ServiceがAPI結果とDB状態を照合し、更新・削除内容を決める。
5. Repositoryが一括DB反映し、成功時COMMIT、失敗時ROLLBACKする。

Serviceの判定をトランザクション中に実行するためのコールバック設計は実装前に確定する。

## 3. YouTubeライブ・Twitchライブ

- `nowstreamings`は`talent_id`主キーで1タレント1件。
- 新規・継続配信はUPSERTし、検出した配信の`miss_count`を0にする。
- API取得成功時に対象プラットフォームの配信が未検出なら、1回目は`miss_count=1`、2回連続なら削除する。
- APIエラーは未検出回数に数えない。
- 未検出による更新・削除は`talent_id`、`platform`、`external_stream_id`を照合する。
- 同じタレントが両プラットフォームで配信した場合、最後にDBへ正常反映された配信を保持する。API取得順は優先順位に使わない。
- 卒業済み（`is_active=false`）のタレントはAPI同期対象から除外し、既存の配信情報は外部API成功に依存しない共通クリーンアップで削除する。

### Twitch固有

- 登録済みの`twitch_user_id`を対象にHelix streams APIを取得する。
- `first=50`でページネーションし、全ページ取得成功後にDB反映する。途中ページ失敗時はDB変更しない。
- App Access Tokenをキャッシュし、期限前に更新する。401時はトークンを更新して1回だけ再試行する。

### YouTube固有

- APIクォータ節約を優先し、既存方針の検索方式を維持する。検索結果の`channelId`と登録済み`youtube_channel_id`でタレントを照合する。
- ライブ取得とアーカイブ取得は独立して成功・失敗を扱う。

## 4. YouTubeアーカイブ

- `archives.external_stream_id`（YouTube動画ID）に一意制約を設ける。
- 新規アーカイブだけを追加し、既存レコードを削除して再挿入しない。
- `open_date`から14日経過したアーカイブを削除する。
- 新規INSERTと期限切れDELETEを**同一トランザクション**で実行する。
- アーカイブAPI取得に失敗した場合は、期限切れ削除も実行しない。
- 卒業済みタレントのアーカイブも保存期間までは維持する。

## 5. DB競合・再試行

- 対象行のロック取得順は原則`talent_id`昇順とする。
- MySQLデッドロックエラー1213時は初回を含め最大3回、DBトランザクション全体を再試行する。
- 再試行では外部APIを再取得せず、DBの最新状態を再取得してServiceで判定し直す。
- 再試行の間には短いランダムな待機を設ける。具体値は実装時に調整する。
- `context.Context`キャンセル時は再試行を中止する。
- 再試行上限を超えた場合はログを記録し、次回の定期同期に任せる。
- `SELECT ... FOR UPDATE`とUPSERTの細部、分離レベル、新規行の競合は実装・テスト時に検証する。

## 6. ログ

Go標準の`log/slog`を使用し、同期開始・終了、API/DBエラー、追加・更新・削除件数、スキップ理由、再試行を記録する。APIキー、トークン等の秘密情報は記録しない。
